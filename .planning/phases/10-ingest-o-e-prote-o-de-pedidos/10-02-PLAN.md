<objective>
Atualizar a interface do formulário público de oração com campo honeypot acessível, feedback de estado visual acolhedor, reset automático pós-envio e implementar a suíte de testes E2E Playwright.

Purpose: Prover aos visitantes e membros uma experiência fluida, acessível e segura de envio de pedidos de oração, prevenindo envios de robôs e garantindo cobertura automatizada de testes E2E.
Output: Componente `app/(public)/oracao/PrayerForm.tsx` aprimorado e suíte de testes E2E `tests/e2e/prayer-ingestion.spec.ts`.
</objective>

| Threat | ASVS Category | Severity | Mitigation |
|---|---|---|---|
| Automação maliciosa / Bots | V11: Business Logic / Abuse | High | Campo honeypot oculto via CSS e desabilitado de tabulação (`tabindex="-1"`) atrai scripts de spam sem impactar humanos (D-01) |
| Vazamento de Dados no Front-end | V4: Access Control & Privacy | Medium | Alternância do switch de anonimato remove o campo visual de nome e zera o estado local para evitar retenção residual |
| Submissões Duplicadas por Clique Rápido | V11: Business Logic / Abuse | Medium | Botão de submit desabilitado automaticamente durante o processamento via `useFormStatus` |
| Injeção no Client / XSS Refletido | V5: Validation & Sanitization | High | Mensagens de retorno renderizadas como nós de texto seguros em container de alerta acessível |
</threat_model>

<action>
1. Atualizar `app/(public)/oracao/PrayerForm.tsx` adicionando suporte completo ao honeypot conforme D-01:
   - Inserir container de honeypot com `style={{ display: "none" }}`, classe `hidden`, `aria-hidden="true"`.
   - Adicionar input de texto `name="honeypot"` com `id="honeypot"`, `tabIndex={-1}`, `autoComplete="off"`.
2. Integrar o formulário à Server Action `submitPrayerRequest` de `@/app/actions/prayer` utilizando `useActionState`:
   - Declarar `const [state, formAction] = useActionState(submitPrayerRequest, null)`.
   - Criar referência `formRef = useRef<HTMLFormElement>(null)`.
   - Adicionar `useEffect` que, ao detectar `state?.success === true`, executa `formRef.current?.reset()`, zera `requestText` para vazio `""`, e reseta `isAnonymous` para `false`.
3. Manter estado reativo para modo anônimo (`isAnonymous`):
   - Checkbox com `id="is_anonymous"`, `name="is_anonymous"`, `value="true"`.
   - Quando `isAnonymous` for `false`, renderizar campo de nome com label 'Seu Nome', validação e exibição de erro `state?.errors?.name`.
   - Quando `isAnonymous` for `true`, omitir o campo de nome do DOM para reforçar privacidade e acolhimento (D-04).
4. Aprimorar a caixa de feedback visual acessível:
   - Container com `role="alert"` e `aria-live="assertive"`.
   - Em caso de sucesso: estilos `bg-verde-50 border border-verde-200 text-verde-800` com ícone `CheckCircle` de `@phosphor-icons/react` (`weight="fill"` e cor `text-verde-600`).
   - Em caso de erro: estilos `bg-red-50 border border-red-200 text-red-700` com ícone `WarningCircle` (`weight="fill"` e cor `text-red-600`).
5. No botão de submissão `SubmitButton`, usar `useFormStatus` para desabilitar o botão durante `pending`, alterando o texto para 'Enviando...' e prevenindo múltiplos cliques acidentais.
6. Manter o contador de caracteres no textarea do pedido (`requestText.length/1000`) com limite máximo de 1000 caracteres.
</action>
