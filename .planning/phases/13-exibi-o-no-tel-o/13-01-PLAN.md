<objective>
Implementar a interface front-end em tela cheia otimizada para projetar pedidos de oração na igreja, acessível exclusivamente através da rota dinâmica `/telao/[token]`, com validação de segurança do token, layout fullscreen de alto contraste em grade 2x2, controle manual de avanço de lotes pelo operador e marcação de pedidos exibidos via API.

Purpose: Prover à equipe de mídia e som da IBBE uma tela limpa, segura e de alto impacto visual para projetar orações da congregação no telão do santuário durante o momento de oração congregacional.
Output: Página Server Component `app/telao/[token]/page.tsx`, componente interativo `app/telao/[token]/TelaoDisplay.tsx` e suíte de testes E2E `tests/e2e/telao-display.spec.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operador / Visitante → `/telao/[token]` | Acesso à rota pública dinamicamente protegida por token secreto |
| TelaoDisplay (Client) → `/api/prayer-requests/*` | Requisições HTTP protegidas por Bearer token transmitidas do cliente para os endpoints do telão |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Information Disclosure | app/telao/[token]/page.tsx | critical | mitigate | Validar no servidor se o token da rota é idêntico a `TELAO_API_TOKEN`; se inválido, abortar a renderização com mensagem de não autorizado |
| T-13-02 | Tampering | app/telao/[token]/TelaoDisplay.tsx | medium | mitigate | Garantir que o token repassado nos headers `Authorization: Bearer ${token}` seja exatamente o token validado |
| T-13-03 | Denial of Service | app/telao/[token]/TelaoDisplay.tsx | low | mitigate | Prevenir múltiplos cliques acidentais no botão de avançar lote desabilitando-o durante requisições ativas |
</threat_model>

<action>
1. Criar `app/telao/[token]/TelaoDisplay.tsx` com a diretiva `"use client"`:
   - Receber prop `token: string`.
   - Definir estado para a lista de orações aprovadas (`prayers: Array<{ id: string, name: string | null, request: string, is_anonymous: boolean }>`).
   - Definir estados para carregamento (`loading: boolean`), erro (`error: string | null`) e ação de avanço (`isAdvancing: boolean`).
2. Implementar busca inicial e atualização de pedidos:
   - Fazer fetch em `GET /api/prayer-requests/display` enviando header `Authorization: Bearer ${token}`.
   - Carregar a lista de pedidos aprovados e não exibidos.
3. Implementar paginação em lotes fixos de 4 pedidos (grade 2x2):
   - O lote ativo consiste nos primeiros 4 itens do array (`prayers.slice(0, 4)`).
   - Renderizar cabeçalho discreto superior com logo/nome "Igreja Batista Bethel — Momento de Oração" e indicador de orações pendentes.
   - Renderizar grade principal `grid grid-cols-2 grid-rows-2 gap-6 p-8 flex-1`:
     - Cada cartão de pedido deve possuir fundo contrastante (`bg-slate-900/90 border border-slate-800 rounded-2xl p-8 flex flex-col justify-between shadow-2xl`).
     - Autor/Nome em destaque com cor âmbar dourado (`text-amber-400 font-semibold text-2xl mb-4`), exibindo "Anônimo" caso `is_anonymous` seja verdadeiro ou `name` seja nulo.
     - Texto da oração em tipografia grande (`text-2xl lg:text-3xl text-slate-100 leading-relaxed line-clamp-6 font-normal`).
4. Implementar tratamento de estado vazio (D-06):
   - Se `prayers.length === 0` e não estiver carregando, exibir slide acolhedor com tema congregacional:
     - Título: "Momento de Oração Congregacional"
     - Subtítulo / Mensagem: "Igreja Batista Bethel em Resende" com versículo de intercessão (ex: Filipenses 4:6 ou 1 Tessalonicenses 5:17).
     - Botão discreto para "Atualizar Fila" caso novos pedidos tenham sido aprovados.
5. Implementar controle de avanço e marcação de exibidos (D-04, D-05, TELA-03):
   - Botão de controle discreto posicionado no rodapé ou canto inferior ("Avançar Lote e Concluir" / "Próximas Orações").
   - Suporte a atalhos de teclado: listener para `keydown` (Barra de Espaço ou Seta Direita) para disparar o avanço.
   - Ao avançar lote:
     - Obter os IDs dos 4 pedidos do lote atual.
     - Disparar em paralelo requisições `POST /api/prayer-requests/[id]/displayed` com header `Authorization: Bearer ${token}` para cada ID.
     - Atualizar o estado local removendo os itens exibidos e, se restarem menos de 4, buscar novos pedidos de `/api/prayer-requests/display`.
   - Adicionar botão opcional de alternar tela cheia nativa (`document.documentElement.requestFullscreen()`).
</action>
