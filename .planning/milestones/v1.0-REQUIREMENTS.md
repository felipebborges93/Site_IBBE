# Requirements — Site IBBE

## v1 Requirements

### Estrutura e Navegação

- [x] **NAV-01**: Menu fixo no topo com navegação por âncoras, rolagem suave e item ativo destacado
- [x] **NAV-02**: Botão flutuante de WhatsApp visível em todas as páginas
- [x] **NAV-03**: Menu mobile responsivo (hambúrguer → drawer/bottom sheet)

### Hero

- [x] **HERO-01**: Seção hero tela cheia com título "Uma igreja feita de _pessoas._" (palavra em Caveat script), subtítulo, mosaico de fotos
- [x] **HERO-02**: Botões CTA "Planeje sua visita" e "Assistir ao vivo" (ao vivo aponta para live se existir)
- [x] **HERO-03**: Faixa inferior com próximo culto calculado automaticamente a partir de `services.ts`

### Nossa História

- [x] **HIST-01**: Resumo na home com texto e link "Leia a história completa"
- [x] **HIST-02**: Página dedicada `/nossa-historia` com texto completo, linha do tempo (2000 → 2003 → Hoje), versículo 2 Crônicas 16.9a, homenagem aos pastores

### Cultos e EBD

- [x] **CULT-01**: Cards de cultos e EBD a partir de `services.ts` com ícone, dia, horário, nome e descrição
- [x] **CULT-02**: Destaque automático (visual diferenciado) para o próximo encontro

### Próximos Eventos

- [x] **EVEN-01**: Cards de eventos a partir de `events.ts`, carrossel no mobile, grade no desktop
- [x] **EVEN-02**: Ordenados por data, eventos com data passada não são exibidos

### Lives do YouTube

- [x] **LIVE-01**: 4 lives mais recentes via YouTube Data API v3 (playlistItems.list + videos.list com liveStreamingDetails)
- [x] **LIVE-02**: Cache com revalidação a cada 30min (ISR/revalidate)
- [x] **LIVE-03**: Fallback em cascata: API → RSS feed público → card amigável "Ver no YouTube"
- [x] **LIVE-04**: Selo "AO VIVO" pulsante quando live em andamento, destaque do card, botão Hero ativo

### Pequenos Grupos (PGMs)

- [x] **GRUP-01**: Lista de PGMs a partir de `groups.ts` com bairro, dia, horário e contato
- [x] **GRUP-02**: Botão "Quero participar" abre WhatsApp com mensagem pré-preenchida ("Olá! Quero conhecer o grupo de [bairro]")

### Ministérios

- [x] **MINI-01**: Cards de ministérios a partir de `ministries.ts` com ícone e descrição

### Ação Social

- [x] **ACAO-01**: Seção de ação social com descrição das atividades da igreja na comunidade

### Pedidos de Oração

- [x] **PRAY-01**: Formulário client-side: campo mensagem (10–1000 chars com contador), nome (opcional), interruptor anônimo
- [x] **PRAY-02**: Se anônimo = true, nome NÃO enviado/armazenado mesmo se digitado
- [x] **PRAY-03**: Validação Zod no cliente E no servidor, mensagens gentis, estados carregando/sucesso/erro
- [x] **PRAY-04**: Campo honeypot oculto + rate limit por hash de IP (sal + hash, nunca IP bruto)
- [x] **PRAY-05**: Tabela `prayer_requests` no Supabase: id, message, author_name, is_anonymous, status (enum), created_at, approved_at, displayed_at, ip_hash
- [x] **PRAY-06**: RLS: anon só INSERT, leitura/moderação só com credencial de serviço
- [x] **PRAY-07**: API `GET /api/prayer-requests/display` protegida por token para futuro telão
- [x] **PRAY-08**: API `PATCH /api/prayer-requests/:id/displayed` (mesmo token) para marcar como displayed
- [x] **PRAY-09**: Área de moderação `/admin/oracao` com auth Supabase (email admin), listar/aprovar/rejeitar/arquivar, mobile-friendly, noindex

### Planeje sua Visita

- [x] **VISI-01**: 3 passos visuais para o visitante
- [x] **VISI-02**: Acordeão de FAQ a partir de `content/faq.ts`
- [x] **VISI-03**: Botão de WhatsApp para contato

### Localização e Contato

- [x] **LOCA-01**: Google Maps iframe com `loading="lazy"`, endereço completo
- [x] **LOCA-02**: Botões "Abrir no Google Maps" (link) e "Como chegar" (link de rota)
- [x] **LOCA-03**: Telefone, WhatsApp, e-mail e redes sociais

### Contribuição (PIX)

- [x] **PIX-01**: Chave PIX exibida com botão "Copiar chave" e feedback visual

### Conteúdo Editável

- [x] **CONT-01**: Pasta `/content` com arquivos TS tipados: site.ts, services.ts, events.ts, groups.ts, ministries.ts, history.ts, faq.ts
- [x] **CONT-02**: Placeholders `[PLACEHOLDER]` claramente marcados onde dados não foram informados

### SEO e Performance

- [x] **SEO-01**: Metadata completa por página, Open Graph com imagem, lang pt-BR
- [x] **SEO-02**: sitemap.xml e robots.txt gerados
- [x] **SEO-03**: JSON-LD tipo Church (nome, endereço, horários, redes)
- [x] **PERF-01**: Lighthouse ≥ 90 em todas categorias mobile
- [x] **PERF-02**: Imagens WebP/AVIF via next/image, fontes display:swap, sem JS desnecessário

### Acessibilidade

- [x] **A11Y-01**: HTML semântico, contraste WCAG AA, navegação por teclado
- [x] **A11Y-02**: `alt` em todas as imagens, respeito a `prefers-reduced-motion`
- [x] **A11Y-03**: Labels reais no formulário, foco visível, `aria-live` nas mensagens de status

### Privacidade (LGPD)

- [x] **LGPD-01**: Página `/privacidade` em linguagem clara sobre dados dos pedidos de oração
- [x] **LGPD-02**: Aviso de privacidade no formulário de oração
- [x] **LGPD-03**: Sem cookies de rastreamento; analytics leve sem cookies se necessário

### Segurança

- [x] **SEC-01**: Nenhuma chave/segredo no repositório, `.env.example` documentado
- [x] **SEC-02**: Cabeçalhos de segurança (CSP, X-Frame-Options, etc.)
- [x] **SEC-03**: Validação/sanitização de entrada no servidor, nunca renderizar HTML do usuário

### Testes

- [x] **TEST-01**: Teste do cálculo "próximo culto"
- [x] **TEST-02**: Teste da validação do formulário (incluindo caso anônimo)
- [x] **TEST-03**: Teste do fallback do YouTube

### Documentação

- [x] **DOC-01**: README em português (como rodar, editar conteúdo, configurar env, publicar)
- [x] **DOC-02**: `docs/telao-api.md` — contrato das rotas do telão + Supabase Realtime
- [x] **DOC-03**: Lista final de placeholders a preencher
- [x] **DOC-04**: Checklist de configuração externa (Supabase, YouTube API, domínio)

## v2 Requirements (Deferred)

- Webapp do telão para projetar pedidos de oração aprovados em tempo real
- Blog / devocional online
- Cadastro de membros com área logada
- Transmissão ao vivo embutida (player inline) em vez de link externo
- Notificações push para eventos e lives
- Dark mode

## Out of Scope

- App mobile nativo — site responsivo é suficiente para o público-alvo
- Multi-idioma — apenas pt-BR
- E-commerce / loja — não aplicável
- Sistema de dizimação com gateway de pagamento — apenas exibição de chave PIX
- Agenda pastoral / gerenciamento interno — seria outro sistema
